先载入地图所需资料，其余完整酒库按需加载。发布包使用无损 gzip 酒库分片，保留所有记录、图片与出处，并在构建时检查 GitHub Pages 的 1 GB 容量上限。首次载入体验已在本机受限网络模拟中验证；实际速度取决于设备与网络。仍有酒款缺少介绍、实物图或诞生年份，全球国家及 Untappd 获奖资料尚未补全。

以下章节保留此前补充批次的统计与制作记录，当前总数以本节和生成目录为准。

## 手机加载与完整酒库

发布目录仍保留完整数据库，按字节预算拆为 JSON 分片及一份清单，每个文件不超过 8MiB。首屏先展开地球与原料产区，再加载独立的 `data/catalog.bootstrap.json` 和酒瓶图片。底图与轻量国家轮廓并行读取，精确海陆位图保持原 50m 几何的判定精度；详细国家边界随后载入。首屏目录只有符合地图要求的酒款和关联酒厂，来源核验全文保留在完整分片中。进入需要完整数据的酒库、收藏或搜索，或打开首屏子集中没有的酒款链接时，再最多并发加载 4 个完整分片；地方酒款等已完整包含在首屏目录中的集合无需重复加载。完整酒库的记录、顺序和字段不变，不通过删数据缩短加载时间。

## 地形、国家与酒精度

地球沿用 Natural Earth 原版柔和地形阴影，调整为偏中性的浅灰绿陆地和更清楚的蓝色海洋；参考平滑后的历史地表颜色，轻微区分沙漠与冰雪。手机请求约 117 KB 的 2048px 底图，大屏请求约 372 KB 的 4096px 底图。素材、来源及可复现处理记录均在 `public/maps/earth-terrain*`。这是地形阴影底图，未把山体做成高度网格。

点陆地可选择国家并高亮边界，只显示该国家在当前筛选下的酒；点海洋或国家标签的关闭按钮可恢复全球。拖动地图不会触发国家筛选，选择国家不会自动移走相机。

底部双滑条按 ABV 范围即时筛选，键盘每步 0.1%；采用非线性刻度保留高酒精度来源记录，同时给常见低度酒更长的操作区间。默认包含未知度数；设置范围后只匹配已知数值，清除后恢复。

## 原材料产区与季节

地球默认显示 9 类原材料的 38 个代表种植产区：大麦、啤酒花、小麦、燕麦、黑麦、柑橘、芫荽、咖啡和可可。3D 模式把原料画成会轻微摆动的微缩作物片区，每处由 20 簇紧密相邻的小植物组成，单株小于酒瓶：金色麦穗、酒花藤、咖啡红果及可可荚等；随地球真实旋转，不使用固定屏幕图标。平面模式使用同一模型导出的透明图片。位置是经资料核对的区域示意中心，并非农场地址或附近酒厂的真实采购关系。3D 原料景观位于酒瓶层下方，不占用酒瓶展示名额；平面模式的原料图片避让酒瓶。右侧酒瓶与麦穗按钮可独立开关，关闭酒瓶可单独看植物，点击原料或地图下方提示可查看说明、生长采收季节、适生气候和出处。每个产区介绍附 1–3 款有图的附近、本国或有原料依据的酒款；明确区分相关展示与真实采购关系。下拉选择产区会自动定位并适度放大。

植物形状为项目原创低面数几何，按类型共享资源；38 处成片植物复用共享几何，手机版约 62.9 万三角面，大屏约 100.3 万，共 76 次绘制；不拉取外部图片。

产区介绍展示该作物在当地的适宜季节、采收时间与气候条件，并保留农业资料出处。没有实时天气按钮、天气图标或天气接口请求。季节按南北半球和当地种植制度区分；热带作物按雨旱季、连续生长与主要采收期说明。

本地冷启动测试（最终数据）：390×844、DPR 2、4 Mbps/80 ms、CPU 4 倍减速、禁用缓存，约 2.7 秒地球及 38 处产区可交互，4.8 秒出现第一张酒瓶图，至此传输约 1.43 MB。这是本机 Chrome 的受限网络模拟，不是所有手机或 GitHub Pages 的速度保证。完整酒库仍保留，首次进入完整搜索需要另行加载。报告：`qa/v136-mobile-load-lazy-routes.json`。

本机 Chrome 的桌面 1440×900 与手机 390×844 视口各连续拖动 10 秒，分别约 59.9 FPS，未测得超过 50 ms 的长任务；测试时 38 处植物开启，结束时分别保留 116/73 张可见酒图。报告：`qa/v136-frame-after-drag.json`。这是本机浏览器测试，不等同于所有手机硬件表现。

本轮 285 项自动检查通过；38 产区的 1–3 款推荐在手机逐项验收，小屏无横向溢出；WebGL 渲染异常可回退平面地图并继续加载。原先的开关断言把一个从未显示的隐藏候选被移出 DOM 误报为重建，现分别检查原可见节点保持、现存节点替换和重新加载；78 个原可见节点保持不变。

## GitHub Pages 部署

仓库 Settings → Pages 中将 Source 设为 GitHub Actions。推送到 `main`，或在 Actions 手动运行 `Deploy Brew Atlas to GitHub Pages`，即可构建、运行全部测试并部署。

工作流自动读取 Pages 的子目录路径，酒瓶图片、地图、数据和来源说明均使用同一路径。无需手改资源地址。网站地址见成功的部署任务输出。

`dist/`、测试截图、抓取工具缓存及本机认证信息均不提交到 GitHub。

## 构建与核验

`npm run build` 先恢复输入快照、生成获奖/代表中间目录，再合并数据，最后构建页面和打包实际引用的图片。完整工作文件保留在 `public/data/catalog.json`，不提交 Git；运行网站先使用小型地图目录，完整查询使用 `data/catalog.manifest.json` 及其分片。打包同时保留地图 GeoJSON、JS/CSS 和目录的 gzip 版本及未压缩文件；地图压缩只改变传输形式，不修改海陆几何。`npm test` 运行数据、合并、分类、地图、分片恢复与加载等检查。

- scripts/build-curated-catalog.mjs：精选中间目录 public/data/curated.json。
- scripts/build-local-catalog.mjs：完整运行目录和合并审计。
- scripts/restore-data-snapshots.mjs：恢复压缩输入并验证完整性。
- scripts/catalog-chunks.mjs：按字节预算生成完整数据分片。
- scripts/catalog-bootstrap.mjs：生成首屏地图子集，保留分类、图片去重与全库数量语义。
- scripts/compressed-assets.mjs：为地图和 JS/CSS 生成 gzip 文件，保留原文件。
- research/local-catalog/：压缩数据输入及完整性清单。
- scripts/local-catalog.test.mjs：旧库恢复和来源合并检查。
- scripts/marker-layout.test.mjs：图片尺寸、部分重叠、沿海布局和缩放稳定性检查。
- scripts/catalog-loader.test.mjs：地图首屏单独加载、按需完整加载、错误处理、取消请求和部署路径检查。
- scripts/image-cutouts.test.mjs：透明衍生图、源图溯源和显示尺寸检查。
- scripts/restore-data-snapshots.test.mjs：压缩输入恢复、校验与损坏拒绝检查。

浏览器验收报告和截图属于本地 `qa/` 产物，不随源码仓库发布。

代表 1000 仍是选样目标；当前6款为种子，不把大量普通酒款自动标成代表。软件许可见 `THIRD-PARTY-NOTICES.md`；数据和图片的来源、署名与许可说明分别保留在 `public/data-sources/` 与 `research/*-SOURCES.md`。
